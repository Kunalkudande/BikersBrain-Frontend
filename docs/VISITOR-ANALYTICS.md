# Visitor analytics

Deploy the backend first, then the frontend, because the new dashboard requires the expanded analytics response. Before starting the new backend, run `npm run prisma:migrate:prod` and `npm run prisma:generate` in the backend project. Migration `20261018003000_visitor_analytics` adds campaign fields, last activity, event deduplication, cart events and optional order/session attribution. No existing orders or catalog records are deleted or backfilled with invented attribution.

The admin Visitors page shows session starts, page views, sessions adding to cart, sessions with orders, traffic sources/campaigns, most-viewed products, comparisons, daily trends and full paginated journeys. Date boundaries use Asia/Kolkata. The current period includes today; its previous comparison has equal elapsed time. Days without sessions show zero.

Metrics use sessions that start within the selected period. Page views, cart adds and orders must also fall within that period. A browser tab gets a new session after 30 minutes without a tracked interaction. Session counts are not exact people counts: tabs, devices, disabled storage, blockers and shared IPs affect measurement. Unique IPs are labelled separately.

Source attribution uses the first page's UTM source/medium/campaign, otherwise its external referrer. Referrers are stored as HTTP(S) origins without query strings or credentials. Internal referrers and missing sources are Direct / unknown. The historical referrers can supply approximate traffic sources; historical campaign parameters were not collected. Campaign attribution stays with a session until it expires. UTM-tagged links can be used in new advertisements and social posts.

Cart events are sent only after a successful cart add, not merely a cart-page visit. The ordered funnel requires a product page, then a cart event, then checkout, then a qualifying order in the same session. A qualifying order is paid online or COD, excluding cancelled/returned orders. The separate orders card includes qualifying sessions even if they skipped a funnel step. Visiting `/order-success` cannot create a conversion. Pending/failed online payments are excluded. New events and order attribution are available only after deployment; older funnel stages may be incomplete. Refund/return/cancellation can change counts when data is refreshed.

Signed-in admins are excluded on both frontend and tracking API. Admin/API/private account routes are rejected from tracking. Known bot user agents are marked and excluded by default, with an Include likely bots filter; detection is approximate and hosting/VPN flags alone do not prove a bot. Anonymous staff browsing cannot be identified retrospectively. Location is an IP-network estimate.

The public tracker accepts only page views and successful-cart client events with bounded fields, strips page queries/fragments, validates product events and deduplicates event UUIDs. Public analytics are indicative, not tamper-proof. It never accepts purchase completion from the browser. Tracking uses a bounded network timeout and errors cannot block shopping. Admin insights and journey endpoints use the existing admin authentication and role checks. Journeys load 100 pages at a time with Load more.

Checks: frontend `npm test`, `npm run build`, `npm run test:seo`, `npx tsc --noEmit -p tsconfig.app.json`; backend `npm run build`, `npx ts-node tests/visitorAnalytics.validation.ts`, `npx ts-node tests/visitorAnalytics.integration.ts`. Optional SQL verification against the configured PostgreSQL connection: `npx ts-node tests/visitorAnalytics.sql.ts`. SQL fixtures use only temporary tables in one transaction and do not insert real visitors, carts, orders or products.
